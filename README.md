# dsh-task-dag —— 项目任务图谱插件

把「一个项目 = 一张不断生长的任务 DAG」做成 DeepSeek Harness Web GUI 的一等公民：
节点是任务，节点上的**前置条件**是依赖，每个节点挂一条**按顺序接力**的会话链。

它解决的是一个具体问题：**任务进度散落在几十个会话里**。图谱把「做到哪了」「下一步做什么」
从会话历史里提出来，变成一张随项目代码一起流动的图。

---

## 1. 核心概念

```
Workspace（项目） 1 ──── 1 Graph
Graph      1 ──── n Node（任务，五态）
Node       1 ──── n Condition（前置条件，可独立增删改）
Node       n ──── n Node（Edge：A 满足 B 的某个前置条件）
Node       1 ──── n Session（有序交接链，至多一个"当前"）
Session    n ──── 1 Node（一个会话只属于一个节点）
```

四条不会变的设计约定：

1. **项目 = workspace**，一个 workspace 一张图，图存在项目目录里，跟着 git 走。
2. **状态与条件只存节点自己的事实**。「能不能开始」永远由条件满足情况算出来，绝不落盘。
3. **会话链是顺序的，不是集合**。新会话接手旧会话的任务时，旧会话"退休"但保留记录，
   仍然可以打开、可以切回。**退休不等于删除。**
4. **交接不是 fork**。交接是**新建空会话 + 一份短的确定性简报**，目的是压缩上下文。

## 2. 五种节点状态

| 状态 | 中文 | 语义 | 参与可开始计算 |
|---|---|---|---|
| `planned` | 待规划 | 还没拆解/没准备好，先在图上占位 | 否 |
| `todo` | 待开始 | 已就绪；条件全部满足即可开始，否则被阻塞 | 是 |
| `doing` | 进行中 | 正在执行 | 否 |
| `done` | 已完成 | 只有已完成能实现前置条件 | 否 |
| `failed` | 已失败 | 失败终态；不能作为任何节点的前置 | 否 |

颜色沿用节点卡片左侧色条与状态点的现有样式，五种颜色与「任务看板」插件一致：

| 状态 | 颜色令牌 |
|---|---|
| 待规划 | `--dsw-alias-label-tertiary` |
| 待开始 | `--dsw-alias-state-business-primary` |
| 进行中 | `--dsw-alias-state-warn-primary` |
| 已完成 | `--dsw-alias-state-success-primary` |
| 已失败 | `--dsw-alias-state-error-primary` |

**已失败节点的约束**：

- 不能作为其他节点的前置（连边会被拒绝）。
- 把节点改成「已失败」时，如果它还有后继，默认拒绝；必须显式选择「失败并解除依赖」，
  它会同时解除全部出边。这样不会留下"永远等不到"的后继。

## 3. 前置条件（不是直接的前序节点）

每个节点持有自己的**前置条件**列表，例如「需求评审通过」「接口层完成」「外部审批」。

- 条件可以**单独添加**，也可以改名、删除；条件与节点是两回事。
- **连边**表示「A 满足 B 的某个前置条件」，边记录的是 `to.conditionId`，不是裸的 A→B。
  连边时必须选择 A 满足哪个条件（也可以现场新建条件）。
- 同一条条件可以被多个节点满足（**任一已完成即满足**，即 OR）。
- 一个节点可以有多个条件，**全部条件都满足**才能开始（即 AND）。
  需要"两个条件都必须"就建两个条件；需要"A 或 B 完成即可"就让 A、B 连到同一个条件。
- 没有任何条件的节点可以直接开始；声明了条件却没人满足的节点会被有意阻塞。

对外的派生结果（永远不落盘）：

- `ready(n)`：状态为待开始，且所有条件满足。
- `blocked(n)`：状态为待开始，且至少一个条件未满足。
- `progress`：完成数、总数、可开始、阻塞、进行中、失败、待规划；只反映计数，不含「项目是否结束」标志。

**项目里程碑**：一张图最多一个里程碑节点（原来的"收尾节点"）。里程碑只是给一个节点打的标记：
可以是任意状态，**可以作为其他节点的前置**，没有特殊连边限制。里程碑节点完成只表示这个节点
自己完成了，**不代表项目结束**；项目里其他节点仍按各自的状态与前置条件独立推进。

## 4. 每个节点的执行设置与定时执行

### 4.1 Agent 预设与模型

每个节点可以单独绑定：

- `agentPreset`：Agent 预设 id；留空跟随宿主默认。
- `model`：模型 id（`provider/model` 或裸模型 id）；留空跟随宿主默认。
- `reasoningEffort`：推理强度 id（由所选模型提供）；留空使用该模型的默认强度。

模型与推理强度用一个与 DSH 对话输入框一致的 combobox 选择：先选模型，模型公布推理强度时再选一档。
模型目录优先直接读宿主的 LLM registry（因此与 DSH 对话里看到的提供方、模型名和推理强度一致），
读不到时退回 `session/modelCatalog`。
节点上挂接的**当前会话**会立即应用这组配置；「交接新会话」和「定时执行」新建会话时也会带上它。
应用失败只记警告，不会阻断图操作，会话继续使用原配置；警告会显示在界面底部的状态提示里。

### 4.2 定时执行

每个节点可以配置一条 5 段 cron（`分 时 日 月 周`，本地时区），例如 `0 9 * * 1-5`。

Host 侧每 30 秒扫描一次，到期后：

1. 先按「从当前时间往后算」推进下一次执行时间，**不补跑**停机期间错过的执行。
2. 不满足以下任一条件就跳过，并记录原因：节点状态是待开始、所有前置条件已满足、
   没有正在运行的当前会话、宿主会话网关可用。
3. 通过后按顺序：提交「进行中」→ 用节点的预设/模型建新会话 → 挂到节点会话链
   （`handoff.mode = 'scheduled'`）→ 改名 → 发送确定性执行简报。
4. 每 5 秒检查一次执行会话；轮次正常结束则节点改「已完成」，`turn/end` 报错则改「已失败」
   并解除出边。人在这期间改了节点状态或换了当前会话，就尊重人的修改，不覆盖。

调度状态（下次执行时间、上次触发/结果/错误）随节点保存在 `graph.json` 里，跟 git 一起走；
重启后节点仍处于进行中时，会重新接上对 `lastSessionId` 的结算跟踪。

## 5. 安装

插件以「本地 bundle」的形式装进当前 profile：

```text
plugin_manager install_bundle  target = <插件目录绝对路径>
```

安装会做三件事：把包写进 profile 的依赖、把 bundle 名追加到 `dsh.profile.bundles`、
在当前 GUI 里加载它的两个面（Host 与浏览器）。

- **首次安装后需要重启一次 DeepSeek Harness**：包位置发生变化时，加载器要求重新启动才能
  载入新的模块代次（安装结果会明确写出 `restart-required`）。
- 之后只改本目录里的代码 → 重启即可生效；改界面文件后刷新页面也会重新取 bundle。
- 想停用：把 bundle 从 profile 的 bundles 列表里去掉（或 `set_bundle` 关闭）后重启。

## 6. 怎么用

侧栏多出一个「任务图谱」入口，点开是整列的三栏界面：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 项目 ▾  3/8 完成 · 2 个可开始                                        │
├──────────┬───────────────────────────────────────┬───────────────────┤
│ 项目列表 │            SVG 画布                    │   节点详情        │
│ 项目A ●  │   节点 = 任务卡片，箭头 = 满足的条件    │  状态 / 条件      │
│ 3/8      │   分层避交叉；拖动节点推开重叠      │  执行设置 / 定时   │
│ 项目B ●  │   双击空白新建；拖右缘手柄连边           │  会话链 / 任务描述 │
└──────────┴───────────────────────────────────────┴───────────────────┘
```

- **布局**：左右两栏之间的分隔条可以拖动，宽度会记住；也支持选中分隔条后用左右方向键微调、
  双击恢复默认宽度。中间画布始终保留最小宽度。
- **字体**：插件的字号和字体跟随 DSH「设置 → 通用 → 字体大小」的全局值
  （`--dsh-content-font-size`），缩放面板不会出现局部字号偏小。
- **左侧是跨项目总览**：每个项目一行，显示进度和当前可做数，点一下切图。
- **画布**：滚轮缩放、拖背景平移、拖节点记位置、双击空白建节点、从节点右缘拖到另一个节点
  连边；连边后选择它满足目标节点的哪个前置条件（也可以现场新建）。边会主动绕开它不连接的
  节点：普通曲线若会穿过无关节点，就改走带圆角的正交绕行路径，平行边之间仍保持分道。
  - **自动布局**按拓扑深度分层，层内用重心排序和相邻交换尽量消除可避免的边交叉；
    互不相连的子图会各自布局后竖向排开，不会叠在一起；孤立节点集中打包成网格。
  - **布局模式**按钮位于「新建节点」和「自动布局」之间，样式与自动布局相同，按钮文本显示
    「布局模式：自由 / 布局模式：网格」，点击切换：
    网格布局使用 320×198（宽高比约 1.616，黄金比例）的矩形网格，节点中心吸附到网格中心；
    切换时会把所有节点吸附到互不重复的格子并记住模式，网格模式下还会显示淡色网格线。
  - **拖动节点**时，自由布局下落点会实时把其他重叠节点沿最小位移方向推开，并级联处理被推开的节点；
    网格布局下卡片在拖动过程中连续跟随指针，松手后才吸附到最近的空格子。
    松手后保持新落点直到 Host 快照确认，不会先闪回旧位置；连线始终跟随端点自动重排。
- **节点详情**（从上到下）：
  - **标题 → 任务描述 → 状态**：任务描述就是原来的「备注」，支持 Markdown 的「编辑 / 预览」，
    工具栏提供加粗、斜体、行内代码、列表、引用和标题；描述框下方的拖动条可以调整高度，
    高度也会记住。标题、任务描述、cron 与条件重命名都会在停顿后自动保存（后台静默提交，
    不会禁用输入框或抢走焦点），并在失焦、切换节点/项目或关闭详情面板前先冲刷草稿，
    不会因点选别的节点而丢失；
  - **前置条件**：添加、重命名、删除，查看每个条件被哪些节点满足、是否已满足；
  - **完成后解锁**：列出这个节点会满足哪些后继条件；
  - **会话链**：当前会话高亮，已交接的灰显、可「切回」、可「打开」；显示上下文水位，
    超过 60% 出现「建议交接」；
  - 勾选「项目里程碑」；里程碑节点的「里程碑」标记显示在节点上方外侧、与卡片右对齐；
  - **执行设置**（默认折叠）：Agent 预设，以及与 DSH 对话一致的「模型 + 推理强度」combobox；
    这里的选择会立即应用到节点当前的会话，也会用于之后新建的会话；
  - **定时执行**（默认折叠）：开关、cron、常用预设、下次执行时间、上次结果；
  - **危险操作**（默认折叠）：归档整条会话链、删除节点（可勾选同时归档整条会话链）。
- **操作反馈**：新建、连边、改状态等操作的结果提示浮在中间画布栏的底部，出现和消失都不会
  推动画布或改变主视图的位置。
- **删除节点**有两种方式：`splice` 会把上游节点接到后继的前置条件上；`unlink` 只断开关系。
  失去全部满足者的条件会在结果里被列出，提示你去补前置。

### 交接（这是插件的重点）

节点详情里的两个按钮：

| 按钮 | 行为 |
|---|---|
| **交接新会话** | 新建空会话 → 生成简报 → 把简报作为首条消息发出并立即开跑 → 旧会话退休 |
| **交接新会话（空会话）** | 只新建空会话并挂上，不发任何内容，由你开第一句 |

简报是**确定性抽取**（不调模型），包含：任务标题/状态/任务描述、已完成与未完成的前置条件、
完成后会解锁的后续、旧会话最后一条助手回复（截断）、最近 3 条你的请求（各自截断），
结尾要求新会话先复述理解再继续。新会话通常只带 1–2k token，而不是几万 token 的历史。

## 7. Agent 能做什么

插件注册 7 个工具，走工具而不是 HTTP（Agent 的 shell 调 HTTP 会被同源护栏挡住）：

| 工具 | 作用 |
|---|---|
| `graph_map` | 当前项目图：节点、五态、条件与满足情况、可做/阻塞/失败/待规划、里程碑、进度 |
| `graph_next` | 唯一最该做的那个可做节点 |
| `graph_add_node` | 新建节点（可带前置条件、预设/模型/推理强度） |
| `graph_link` | 让一个节点满足目标节点的某个前置条件（服务端环检测） |
| `graph_update_node` | 改标题 / 任务描述 / 五态 / 预设 / 模型 / 推理强度 / 失败时解绑 |
| `graph_add_condition` | 给节点单独添加一个前置条件 |
| `graph_attach_session` | 把**当前会话**挂到节点；节点已有别的当前会话时拒绝，让人去界面交接 |

**Agent 不能做的事**（刻意限制，误判一次可能毁掉整张计划）：删节点、断边、删条件、
归档会话、退休别人的当前会话、改里程碑、配置定时执行。

会话挂到节点之后，每一轮系统提示里会多出四行：当前节点、前置条件满足情况、完成后解锁什么，
以及「用户提出新需求时用 `graph_update_node` 更新任务描述」的维护要求。

即使 Agent 没有实际调用工具，插件也会监听节点**当前会话**的 `user/message`，把最近 6 条用户请求
以「## 对话需求（自动记录）」小节追加到任务描述末尾（交接/定时执行简报、斜杠命令和纯确认语不计入）。
这是确定性的兜底，保证对话推进时任务描述至少跟着更新；Agent 仍可把有效内容整理进上方的正式描述。

## 8. 数据放哪

```
<项目目录>/.dsh-task-graph/
├─ graph.json     # 唯一权威：节点、条件、边、会话链、revision
└─ events.jsonl   # 只追加的审计流（谁在什么时候改了什么）
```

- **随 git 走**：把使用插件的项目里的 `.dsh-task-graph/graph.json` 提交进仓库，团队共享同一张图。
  本仓库是插件开发仓库，它自己运行时写出的 `.dsh-task-graph/` 含有本机绝对路径和会话 id，
  已在 `.gitignore` 中排除，不随源码提交。
- **多窗口安全**：每次写入都带 `expectedRevision`，对不上返回 409 并提示刷新，不会互相覆盖。
- **原子写**：先写临时文件 → fsync → rename；先追加审计行再替换图文件。
- **损坏隔离**：`graph.json` 解析失败时改名为 `graph.json.corrupt-<时间>-<pid>` 并留一条警告，
  插件照常启动，不会因为一个坏文件打不开面板。
- **版本迁移**：当前 `schemaVersion: 2`。读到 v1 文档时会就地迁移：
  原来的收尾节点变成里程碑，每条旧的前序边变成一个独立条件（保持原来的 AND 语义），
  节点补上预设/定时字段，下一次提交写回 v2。

`graph.json` 结构（节选）：

## 9. 代码结构

Host 半（Node）与浏览器半（浏览器）在同一个包里，靠 `package.json` 的 `dsh` 字段声明：

| 文件 | 作用 |
|---|---|
| `index.js` | Host 入口：装配 store / routes / tools / prompt / scheduler，每个面独立容错 |
| `src/model.js` | 纯函数：五态、条件派生、环检测、迁移、删除拼接、链不变量 |
| `src/store.js` | 图文件读写：revision CAS、按 workspace 串行、原子写、损坏隔离、订阅 |
| `src/ops.js` | 所有变更语义的唯一入口（HTTP 与工具共用同一条路径），含执行结算纯函数 |
| `src/sessions.js` | 会话适配：批量取事实、读尾部/事件、确定性简报、建会话、选模型、目录、归档 |
| `src/cron.js` | 无依赖 5 段 cron 解析与下次执行时间计算 |
| `src/scheduler.js` | 每节点定时执行：扫描、跳过规则、启动、执行结果结算 |
| `src/services.js` | 可选服务的读取（`ctx.get` 不受 `inject` 限制，直接 `ctx.xxx` 会抛错） |
| `src/routes.js` | `GET /state`、`/workspaces`、`/catalog`、`POST /action`、`GET /events`(SSE) |
| `src/tools.js` | 7 个 Agent 工具 |
| `src/prompt.js` | 每轮注入的四行节点上下文与任务描述维护要求 |
| `src/description.js` | 监听当前会话的用户消息，自动把最近请求回写到任务描述 |
| `src/workspaces.js` | workspace 解析（含 `cwd` 兜底匹配） |
| `client.js` | 浏览器半：单文件模块，注册 `main` 面板与侧栏入口，手写 SVG 画布；自由/黄金比例网格布局、自动布局避交叉、连边绕开无关节点、拖动推开重叠节点、三栏可调宽、任务描述支持 Markdown 编辑/预览与高度调整、文本草稿自动保存并在切换前冲刷、模型与推理强度 combobox、DSH 风格 K/M token 计数、操作提示浮在画布栏底部 |
| `test/` | `node:test` 单元与集成测试 |

**没有构建步骤**：Host 是普通 ESM；浏览器半是手写的 `window.__ModuleLoader__.load(...)` 模块，
只从平台种子表取 `react`，因此改完代码不需要 tsc/tsdown。插件目录在 profile 之外，
所以**不要**在插件代码里 import `@deepseek-ai/*`（解析不到，会把插件变成加载失败）。

## 11. 边界（明确不做）

- 没有「删除会话」：DSH 只有归档。删节点时可选择归档其会话链，归档可恢复。
- 不做跨项目依赖、关键路径、模板批量建图（留给后续版本）。
- 定时执行只处理「单节点的一次会话」，不做多节点编排/流水线；权限提升仍要人工确认，
  插件不会静默提权。
- 定时执行是尽力而为：执行会话在运行中被删除时只记录结果、不自动改节点状态；会话已空闲
  但事件里没有 `turn/end` 时会继续等待跟踪。遇到这两种情况需要人到界面上把节点改回
  「待开始」或「已失败」。
- 画布是手写 SVG，不做框选、不做上千节点虚拟化。
- 自动布局是分层启发式：尽量消除可避免的边交叉，但不保证全局最少交叉；手动位置不会被自动覆盖，
  只有点「自动布局」才会清除手动位置。拖动避让只处理节点矩形之间的重叠，不重排整张图。
- 网格布局使用固定的 320×198（约黄金比例）网格，不提供自定义格子尺寸；网格模式下拖动过程中卡片
  连续跟随指针，松手后才吸附到最近的空格子，不支持拖动中的自由微调。
- 任务描述的「对话需求（自动记录）」小节是确定性兜底，最多保留最近 6 条用户请求，不做语义摘要；
  真正整理需求仍由人或 Agent 改写上方描述。自动记录只跟随节点的**当前**会话，退休会话不参与。
- `main` 面板切走即卸载；视口、选中态、三栏宽度、布局模式与任务描述高度存在 `localStorage`，切回来会恢复。
- 浏览器 bundle 热重载会让 `main` 注册表短暂变化，ui-layout 因此回退到对话；插件会记住「用户当时在任务图谱面板」并在重新注册后恢复一次。用户主动切回对话时不会触发恢复。
- 交接简报是确定性抽取；模型摘要留到后续版本。
